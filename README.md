# Dependency Visualizer

CLI-приложение на Swift для построения и анализа графа зависимостей
пакетов npm.

Проект выполняется по варианту 15 практической работы по дисциплине
«Конфигурационное управление».

## Текущий этап

Этап 4. Дополнительные операции.

Приложение:

- читает настройки из YAML;
- получает метаданные напрямую из npm Registry;
- извлекает прямые и транзитивные зависимости;
- строит граф алгоритмом BFS без рекурсии;
- фильтрует пакеты по подстроке;
- корректно обрабатывает циклы;
- поддерживает локальные тестовые репозитории;
- выводит порядок обхода BFS;
- определяет порядок загрузки зависимостей;
- сообщает, если полный порядок невозможен из-за цикла;
- обрабатывает ошибки конфигурации, сети и репозитория.

Для получения зависимостей не используются npm, другие менеджеры пакетов
или сторонние библиотеки.

## Параметры конфигурации

| Параметр | Назначение |
|---|---|
| `package_name` | Имя корневого пакета |
| `repository` | URL npm Registry или путь к тестовому JSON |
| `test_mode` | Включение тестового режима |
| `output_file` | Имя будущего SVG-файла |
| `filter_substring` | Подстрока для исключения пакетов |

Пример для npm Registry:

```yaml
package_name: "is-odd"
repository: "https://registry.npmjs.org"
test_mode: false
output_file: "dependency-graph.svg"
filter_substring: "@types/"
```

Пример для тестового репозитория:

```yaml
package_name: "A"
repository: "tests/repositories/basic.json"
test_mode: true
output_file: "basic-graph.svg"
filter_substring: "ZZZ"
```

Если `test_mode` равен `false`, параметр `repository` должен содержать URL
с протоколом `http` или `https`.

Если `test_mode` равен `true`, параметр `repository` должен содержать путь
к существующему JSON-файлу.

Параметр `output_file` проверяется, но используется только на этапе 5.

## Формат YAML

Используется простой формат:

```text
ключ: значение
```

Поддерживаются:

- значения в двойных кавычках;
- значения в одинарных кавычках;
- значения без кавычек;
- пустые строки;
- комментарии, начинающиеся с `#`.

Вложенные объекты и массивы в YAML-конфигурации не используются.

## Получение данных из npm Registry

Приложение выполняет запрос:

```text
GET https://registry.npmjs.org/{package_name}
```

Используется заголовок:

```text
Accept: application/vnd.npm.install-v1+json
```

После получения ответа приложение:

1. Проверяет HTTP-код.
2. Декодирует JSON через `JSONDecoder`.
3. Получает версию из `dist-tags.latest`.
4. Находит эту версию в объекте `versions`.
5. Извлекает поле `dependencies`.
6. Передает зависимости алгоритму построения графа.

Не учитываются:

- `devDependencies`;
- `peerDependencies`;
- `optionalDependencies`.

## Построение графа

Граф строится поиском в ширину без рекурсии.

Используются:

- массив `queue` в качестве очереди;
- индекс `currentIndex`;
- множество `discoveredPackages`;
- список смежности.

Алгоритм:

```text
1. Добавить корневой пакет в очередь.
2. Отметить его как найденный.
3. Получить очередной пакет.
4. Загрузить его прямые зависимости.
5. Применить фильтр.
6. Сохранить связи.
7. Добавить новые пакеты в конец очереди.
8. Повторять до завершения очереди.
```

## Обработка циклов при BFS

Множество `discoveredPackages` не позволяет добавлять один пакет в очередь
несколько раз.

Для графа:

```text
A -> B
B -> C
C -> A
```

порядок BFS будет:

```text
A -> B -> C
```

Связь `C -> A` останется в графе, но пакет `A` не будет обработан повторно.

## Фильтрация

Если имя зависимости содержит `filter_substring`, пакет:

- не сохраняется в графе;
- не добавляется в очередь;
- не анализируется на следующих уровнях.

Для графа:

```text
A -> B, X
B -> C
X -> Y
```

и фильтра `X` результат будет:

```text
A -> B
B -> C
C -> нет зависимостей
```

## Порядок загрузки зависимостей

Порядок загрузки строится так, чтобы каждая зависимость находилась раньше
пакета, который от нее зависит.

Для связи:

```text
A -> B
```

порядок загрузки:

```text
B -> A
```

Для расчета используются:

- количество еще не загруженных зависимостей каждого пакета;
- обратные связи от зависимости к зависящим пакетам;
- список пакетов без незагруженных зависимостей;
- множество уже обработанных пакетов.

Сначала выбираются пакеты без зависимостей. После обработки пакета
уменьшается количество незагруженных зависимостей у связанных с ним
пакетов.

Если одновременно доступны несколько пакетов, они сортируются по имени.
Это делает результат детерминированным.

## Циклы в порядке загрузки

Обычный топологический порядок для циклического графа не существует.

Для графа:

```text
A -> B
B -> C
C -> A
```

программа выводит:

```text
Полный порядок загрузки определить невозможно: граф содержит цикл.
Не удалось упорядочить пакеты:
A, B, C
```

Программа не зависает и не создает недостоверный порядок.

## Формат тестового репозитория

Тестовый репозиторий хранится в JSON:

```json
{
  "A": ["B", "C"],
  "B": ["D"],
  "C": [],
  "D": []
}
```

Ключ является именем пакета. Массив содержит его прямые зависимости.

Правила:

- имена состоят из больших латинских букв;
- каждый пакет имеет массив зависимостей;
- каждая зависимость присутствует в файле;
- пустые массивы разрешены;
- циклы разрешены;
- пустой репозиторий запрещен.

## Сравнение со штатным npm

Сравнение выполнено с:

```text
Node.js 26.13.0
npm 11.20.0
```

Для проверки был создан временный проект:

```bash
npm init -y
npm install is-odd --ignore-scripts --no-audit --no-fund
npm ls --all
```

Результат npm:

```text
└─┬ is-odd@3.0.1
  └── is-number@6.0.0
```

Дополнительная проверка:

```bash
npm view is-number dist-tags.latest
```

Результат:

```text
7.0.0
```

Команда:

```bash
npm view is-odd@3.0.1 dependencies --json
```

Результат:

```json
{
  "is-number": "^6.0.0"
}
```

### Итог сравнения

| Критерий | Приложение | npm |
|---|---|---|
| Корневой пакет | `is-odd` | `is-odd@3.0.1` |
| Зависимость | `is-number` | `is-number@6.0.0` |
| Структура графа | `is-odd -> is-number` | `is-odd -> is-number` |
| Порядок представления | Зависимость первой | Корневой пакет первым |
| Разрешение версий | Тег `latest` | Диапазон `^6.0.0` |

Структура зависимостей совпала.

Различие порядка объясняется назначением вывода:

- приложение показывает порядок загрузки, поэтому зависимость идет первой;
- `npm ls --all` показывает логическое дерево, начиная с корневого проекта.

Различие версий объясняется алгоритмом разрешения:

- приложение получает `latest` для каждого пакета;
- npm выбирает версию, удовлетворяющую диапазону родительского пакета;
- `is-odd@3.0.1` требует `is-number` версии `^6.0.0`;
- npm установил `is-number@6.0.0`;
- тег `latest` у `is-number` указывает на `7.0.0`.

## Обработка ошибок

Обрабатываются:

- отсутствие конфигурационного файла;
- неправильный формат YAML;
- отсутствующий или повторяющийся параметр;
- неизвестный параметр;
- пустое значение;
- некорректный URL;
- неправильное значение `test_mode`;
- неправильное расширение выходного файла;
- сетевая ошибка;
- HTTP-ошибка;
- пакет не найден;
- некорректные метаданные npm;
- отсутствие тега `latest`;
- отсутствие версии;
- некорректный тестовый JSON;
- пустой тестовый репозиторий;
- неправильное имя тестового пакета;
- ссылка на отсутствующий тестовый пакет;
- цикл при определении порядка загрузки.

При ошибке программа выводит причину и завершается с кодом `1`.

Цикл в порядке загрузки не завершает приложение с ошибкой. Программа
выводит частичный результат и список неупорядоченных пакетов.

## Основные компоненты

### `YAMLParser`

Читает и проверяет YAML-конфигурацию.

### `Configuration`

Хранит и проверяет пользовательские параметры.

### `NPMModels`

Описывает метаданные npm и зависимости.

### `NPMRegistryClient`

Получает метаданные пакетов напрямую из Registry.

### `TestRepository`

Читает и проверяет локальный JSON-репозиторий.

### `DependencyDataSource`

Переключает источник между npm Registry и тестовым JSON.

### `DependencyGraphBuilder`

Строит полный граф алгоритмом BFS без рекурсии.

### `DependencyGraph`

Хранит список смежности, версии, порядок BFS и статистику.

### `DependencyLoadOrder`

Вычисляет детерминированный порядок загрузки и обнаруживает циклы.

### `main.swift`

Загружает настройки, строит граф и выводит результаты.

### `run.sh`

Собирает и запускает приложение.

### `tests/run_tests.sh`

Проверяет реальные и тестовые сценарии.

## Ограничения текущего этапа

Приложение:

- использует `latest` для каждого npm-пакета;
- не разрешает диапазоны версий как npm;
- не учитывает дополнительные типы зависимостей;
- выполняет HTTP-запросы последовательно;
- не создает описание D2;
- не сохраняет SVG.

D2 и SVG будут реализованы на этапе 5.
