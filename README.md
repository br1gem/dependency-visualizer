# Dependency Visualizer

CLI-приложение на Swift для построения графа зависимостей пакетов npm.

Проект выполняется по варианту 15 практической работы по дисциплине
«Конфигурационное управление».

## Текущий этап

Этап 3. Основные операции.

На текущем этапе приложение:

- читает настройки из файла YAML;
- проверяет корректность всех параметров;
- получает метаданные пакетов напрямую из npm Registry;
- извлекает прямые и транзитивные зависимости;
- строит граф алгоритмом BFS без рекурсии;
- исключает пакеты, содержащие заданную подстроку;
- корректно обрабатывает циклические зависимости;
- поддерживает локальный тестовый репозиторий;
- выводит порядок обхода BFS;
- выводит граф в виде списка смежности;
- обрабатывает ошибки конфигурации, сети и репозитория.

Для получения зависимостей не используются npm, другие менеджеры пакетов
или сторонние библиотеки.

## Параметры конфигурации

Приложение использует пять параметров:

| Параметр | Назначение |
|---|---|
| `package_name` | Имя корневого npm-пакета |
| `repository` | URL npm Registry или путь к тестовому JSON |
| `test_mode` | Включение режима тестового репозитория |
| `output_file` | Имя будущего SVG-файла |
| `filter_substring` | Подстрока для исключения пакетов |

Пример конфигурации для npm Registry:

```yaml
package_name: "is-odd"
repository: "https://registry.npmjs.org"
test_mode: false
output_file: "dependency-graph.svg"
filter_substring: "@types/"
```

Пример конфигурации для тестового репозитория:

```yaml
package_name: "A"
repository: "tests/repositories/basic.json"
test_mode: true
output_file: "basic-graph.svg"
filter_substring: "ZZZ"
```

Если `test_mode` имеет значение `false`, параметр `repository` должен
содержать URL с протоколом `http` или `https`.

Если `test_mode` имеет значение `true`, параметр `repository` должен
содержать путь к существующему JSON-файлу.

Параметр `output_file` проверяется, но создание SVG будет реализовано
на этапе 5.

## Поддерживаемый формат YAML

Конфигурация использует простой формат:

```text
ключ: значение
```

Поддерживаются:

- строковые значения в одинарных кавычках;
- строковые значения в двойных кавычках;
- значения без кавычек;
- пустые строки;
- комментарии, начинающиеся с символа `#`.

Вложенные объекты и массивы в YAML-конфигурации не используются.

## Работа с npm Registry

Приложение формирует HTTP-запрос:

```text
GET https://registry.npmjs.org/{package_name}
```

Используется заголовок:

```text
Accept: application/vnd.npm.install-v1+json
```

После получения ответа приложение:

1. Проверяет код HTTP-ответа.
2. Декодирует JSON стандартным `JSONDecoder`.
3. Получает версию из поля `dist-tags.latest`.
4. Находит выбранную версию в объекте `versions`.
5. Извлекает прямые зависимости из поля `dependencies`.
6. Передает зависимости алгоритму построения графа.

На текущем этапе не учитываются:

- `devDependencies`;
- `peerDependencies`;
- `optionalDependencies`.

## Построение графа алгоритмом BFS

Граф строится поиском в ширину без рекурсии.

Для обхода используются:

- массив `queue` в качестве очереди;
- индекс `currentIndex` для выбора текущего элемента;
- множество `discoveredPackages` для найденных пакетов;
- список смежности для хранения связей графа.

Упрощенная схема алгоритма:

```text
1. Добавить корневой пакет в очередь.
2. Добавить корневой пакет в множество найденных пакетов.
3. Взять очередной пакет из очереди.
4. Получить его прямые зависимости.
5. Исключить зависимости, содержащие подстроку фильтра.
6. Сохранить оставшиеся связи в графе.
7. Добавить новые пакеты в конец очереди.
8. Повторять, пока очередь не будет обработана полностью.
```

Рекурсивные функции для обхода графа не используются.

## Обработка циклов

Для каждого найденного пакета проверяется результат добавления в множество:

```swift
discoveredPackages.insert(dependency.name).inserted
```

Если пакет уже встречался, связь сохраняется в графе, но пакет не
добавляется в очередь повторно.

Например, для графа:

```text
A -> B
B -> C
C -> A
```

порядок обработки будет:

```text
A -> B -> C
```

Связь `C -> A` сохранится, но повторная обработка `A` не произойдет.

## Фильтрация пакетов

Если имя зависимости содержит значение `filter_substring`, зависимость:

- не сохраняется в графе;
- не добавляется в очередь;
- не обрабатывается на следующих уровнях.

Например, при фильтре `X`:

```text
A -> B, X
B -> C
X -> Y
```

результат будет:

```text
A -> B
B -> C
C -> нет зависимостей
```

Пакеты `X` и `Y` не попадут в итоговый граф.

## Формат тестового репозитория

Тестовый репозиторий хранится в JSON-файле.

Пример:

```json
{
  "A": ["B", "C"],
  "B": ["D"],
  "C": [],
  "D": []
}
```

Ключ объекта является именем пакета, а массив содержит его прямые
зависимости.

Требования к тестовому репозиторию:

- имя каждого пакета состоит из больших латинских букв;
- каждый пакет имеет массив зависимостей;
- каждая указанная зависимость присутствует в файле;
- циклические зависимости разрешены;
- пустые списки зависимостей разрешены;
- пустой репозиторий запрещен.

## Обработка ошибок конфигурации

Приложение обрабатывает:

- отсутствие конфигурационного файла;
- невозможность чтения файла;
- неправильный формат строки YAML;
- пустой ключ;
- пустое значение;
- повторяющийся параметр;
- неизвестный параметр;
- незакрытые кавычки;
- пустое имя пакета;
- некорректный URL;
- неправильное значение `test_mode`;
- неправильное расширение выходного файла;
- пустую подстроку фильтрации;
- слишком большое количество аргументов запуска.

## Обработка ошибок npm Registry

Приложение обрабатывает:

- сетевую ошибку;
- некорректный HTTP-ответ;
- ответ `404`;
- другие HTTP-ошибки;
- некорректный JSON;
- отсутствие тега `latest`;
- отсутствие версии, указанной в `latest`.

## Обработка ошибок тестового репозитория

Приложение обрабатывает:

- отсутствие JSON-файла;
- невозможность чтения файла;
- некорректный JSON;
- пустой репозиторий;
- имя пакета не из больших латинских букв;
- ссылку на отсутствующий пакет;
- отсутствие корневого пакета.

При любой ошибке программа выводит причину и завершается с кодом `1`.

## Основные компоненты

### `YAMLParser`

Читает конфигурационный файл, разбирает пары `ключ: значение` и проверяет
структуру YAML.

### `Configuration`

Хранит пять пользовательских параметров и проверяет их корректность.

### `NPMModels`

Содержит структуры для декодирования метаданных npm и представления
зависимостей.

### `NPMRegistryClient`

Формирует URL пакета, выполняет HTTP-запрос, проверяет ответ и получает
прямые зависимости версии `latest`.

### `TestRepository`

Читает локальный JSON, проверяет имена пакетов и целостность ссылок между
ними.

### `DependencyDataSource`

Предоставляет единый интерфейс для npm Registry и тестового репозитория.

### `DependencyGraphBuilder`

Строит полный граф алгоритмом BFS без рекурсии, применяет фильтрацию и
предотвращает повторную обработку пакетов.

### `DependencyGraph`

Хранит список смежности, версии пакетов, порядок обхода и статистику графа.

### `main.swift`

Загружает конфигурацию, выбирает источник данных, запускает построение
графа и выводит результат.

### `run.sh`

Собирает все Swift-файлы системным компилятором и запускает приложение.

### `tests/run_tests.sh`

Проверяет реальный npm Registry, обычный граф, цикл, фильтрацию и обработку
ошибок.

## Ограничения текущего этапа

На этапе 3 приложение:

- использует версию с тегом `latest` для каждого npm-пакета;
- не разрешает диапазоны версий как штатный npm;
- не учитывает дополнительные типы зависимостей;
- выполняет HTTP-запросы последовательно;
- не выводит порядок загрузки зависимостей;
- не создает описание D2;
- не создает SVG-файл.

Порядок загрузки будет реализован на этапе 4. D2 и SVG будут добавлены
на этапе 5.
