# Dependency Visualizer

CLI-приложение на Swift для построения и визуализации графа зависимостей
пакетов npm.

Проект выполнен по варианту 15 практической работы по дисциплине
«Конфигурационное управление».

## Возможности

Приложение:

- читает настройки из YAML;
- проверяет корректность всех параметров;
- получает метаданные напрямую из npm Registry;
- извлекает прямые и транзитивные зависимости;
- строит граф алгоритмом BFS без рекурсии;
- фильтрует пакеты по подстроке;
- корректно обрабатывает циклические зависимости;
- поддерживает локальные тестовые репозитории;
- определяет порядок загрузки зависимостей;
- формирует текстовое описание графа на языке D2;
- выводит D2 в Terminal;
- сохраняет изображение графа в SVG;
- обрабатывает ошибки конфигурации, сети, npm Registry и D2.

Для получения зависимостей не используются npm, другие менеджеры пакетов
или сторонние библиотеки.

Официальный D2 CLI используется только для преобразования самостоятельно
сформированного D2-текста в SVG.

## Требования

Для сборки и запуска необходимы:

- macOS;
- Swift 6 или новее;
- Xcode Command Line Tools;
- D2 CLI;
- интернет для работы с npm Registry.

Использованные версии:

```text
Apple Swift 6.4
D2 v0.9.0
Node.js 26.13.0
npm 11.20.0
```

Node.js и npm нужны только для сравнения результатов. Основное приложение
их не использует.

Проверить инструменты:

```bash
xcrun swiftc --version
d2 version
```

Установить D2 через Homebrew:

```bash
brew install d2
```

## Конфигурация

Приложение использует пять параметров:

| Параметр | Назначение |
|---|---|
| `package_name` | Имя корневого пакета |
| `repository` | URL npm Registry или путь к тестовому JSON |
| `test_mode` | Включение тестового режима |
| `output_file` | Путь к создаваемому SVG |
| `filter_substring` | Подстрока для исключения пакетов |

Пример для npm Registry:

```yaml
package_name: "is-odd"
repository: "https://registry.npmjs.org"
test_mode: false
output_file: "dependency-graph.svg"
filter_substring: "@types/"
```

Пример для тестового репозитория:

```yaml
package_name: "A"
repository: "tests/repositories/basic.json"
test_mode: true
output_file: "basic-graph.svg"
filter_substring: "ZZZ"
```

Если `test_mode` равен `false`, `repository` должен содержать URL с
протоколом `http` или `https`.

Если `test_mode` равен `true`, `repository` должен содержать путь к
существующему JSON-файлу.

`output_file` должен оканчиваться на `.svg`.

## Формат YAML

Используется простой формат:

```text
ключ: значение
```

Поддерживаются:

- значения в двойных кавычках;
- значения в одинарных кавычках;
- значения без кавычек;
- пустые строки;
- комментарии, начинающиеся с `#`.

Вложенные объекты и массивы в YAML-конфигурации не используются.

## Получение данных из npm Registry

Для каждого пакета выполняется запрос:

```text
GET https://registry.npmjs.org/{package_name}
```

Используется заголовок:

```text
Accept: application/vnd.npm.install-v1+json
```

После получения ответа приложение:

1. Проверяет HTTP-код.
2. Декодирует JSON через `JSONDecoder`.
3. Получает версию из `dist-tags.latest`.
4. Находит версию в объекте `versions`.
5. Извлекает поле `dependencies`.
6. Передает зависимости алгоритму построения графа.

Не учитываются:

- `devDependencies`;
- `peerDependencies`;
- `optionalDependencies`.

## Построение графа

Граф строится алгоритмом BFS без рекурсии.

Используются:

- массив `queue` в качестве очереди;
- индекс `currentIndex`;
- множество `discoveredPackages`;
- список смежности.

Алгоритм:

```text
1. Добавить корневой пакет в очередь.
2. Отметить пакет как найденный.
3. Получить очередной пакет.
4. Загрузить его прямые зависимости.
5. Применить фильтр.
6. Сохранить связи.
7. Добавить новые пакеты в конец очереди.
8. Повторять до завершения очереди.
```

## Обработка циклов

Множество `discoveredPackages` не позволяет добавлять пакет в очередь
повторно.

Для графа:

```text
A -> B
B -> C
C -> A
```

порядок BFS:

```text
A -> B -> C
```

Связь `C -> A` сохраняется, но повторная обработка `A` не выполняется.

## Фильтрация пакетов

Если имя зависимости содержит `filter_substring`, пакет:

- не сохраняется в графе;
- не добавляется в очередь;
- не анализируется на следующих уровнях.

Для графа:

```text
A -> B, X
B -> C
X -> Y
```

и фильтра `X` результат будет:

```text
A -> B
B -> C
C -> нет зависимостей
```

## Порядок загрузки

Порядок строится так, чтобы зависимость находилась раньше пакета, который
от нее зависит.

Для связи:

```text
A -> B
```

порядок загрузки:

```text
B -> A
```

Если одновременно доступны несколько пакетов, они сортируются по имени.
Благодаря этому результат остается детерминированным.

Для циклического графа полный топологический порядок невозможен. Программа
выводит понятное сообщение и список неупорядоченных пакетов.

## Тестовый репозиторий

Тестовый репозиторий хранится в JSON:

```json
{
  "A": ["B", "C"],
  "B": ["D"],
  "C": [],
  "D": []
}
```

Ключ является именем пакета. Массив содержит его прямые зависимости.

Правила:

- имена состоят из больших латинских букв;
- каждый пакет имеет массив зависимостей;
- каждая зависимость присутствует в файле;
- пустые массивы разрешены;
- циклы разрешены;
- пустой репозиторий запрещен.

## Формирование D2

Для каждой вершины создается безопасный внутренний идентификатор:

```d2
node_0
node_1
node_2
```

Имя и версия пакета записываются в подпись:

```d2
node_0: "is-odd@3.0.1" {
  shape: rectangle
}
```

Корневой пакет выделяется:

```d2
style.fill: "#dbeafe"
style.stroke: "#2563eb"
style.stroke-width: 2
```

Связь содержит требование к версии:

```d2
node_0 -> node_1: "^6.0.0"
```

Специальные символы в подписях экранируются.

## Создание SVG

Программа:

1. Формирует D2-текст.
2. Выводит его в Terminal.
3. Сохраняет временный `.d2` в `.build/d2`.
4. Запускает D2 CLI.
5. Передает путь из `output_file`.
6. Проверяет код завершения D2.
7. Проверяет наличие SVG.
8. Удаляет временный `.d2`.

Используется команда:

```bash
d2 input.d2 output.svg
```

SVG создается только после успешного завершения D2.

## Сравнение со штатным npm

Штатная команда:

```bash
npm ls --all
```

показывает логическое дерево установленных зависимостей, но не создает
графическое изображение.

Для `is-odd` npm вывел:

```text
└─┬ is-odd@3.0.1
  └── is-number@6.0.0
```

Приложение построило структуру:

```text
is-odd -> is-number
```

Структура зависимостей совпала.

### Различие представления

| Приложение | npm |
|---|---|
| Направленный граф | Текстовое дерево |
| Все уникальные пакеты показаны один раз | Пакет может встречаться в нескольких ветках |
| Связи показаны стрелками | Связи показаны вложенностью |
| Создается SVG | Графический файл не создается |
| Корневой пакет выделен цветом | Корневой проект показан первой строкой |

### Различие версий

`is-odd@3.0.1` требует:

```json
{
  "is-number": "^6.0.0"
}
```

npm установил:

```text
is-number@6.0.0
```

Тег `latest` у `is-number`:

```text
7.0.0
```

Приложение использует `latest` для каждого узла, поэтому показывает
`is-number@7.0.0`.

Для `is-even` это различие заметнее:

```text
is-even@1.0.0 требует is-odd ^0.1.2
```

Приложение строит узел для актуальной версии `is-odd@3.0.1`.

Это ограничение алгоритма разрешения версий, а не ошибка D2 или SVG.

## Обработка ошибок

Обрабатываются:

- отсутствие YAML-файла;
- ошибка чтения YAML;
- неправильная строка YAML;
- пустой ключ или значение;
- повторяющийся параметр;
- неизвестный параметр;
- незакрытые кавычки;
- пустое имя пакета;
- некорректный URL;
- неправильный `test_mode`;
- неправильное расширение выходного файла;
- пустая подстрока фильтра;
- сетевая ошибка;
- некорректный HTTP-ответ;
- пакет не найден;
- поврежденные метаданные npm;
- отсутствие тега `latest`;
- отсутствие выбранной версии;
- некорректный тестовый JSON;
- пустой тестовый репозиторий;
- неправильное имя тестового пакета;
- ссылка на отсутствующий пакет;
- отсутствие D2 CLI;
- ошибка запуска D2;
- ошибка формирования SVG;
- отсутствие итогового SVG.

При ошибке программа выводит причину и завершается с кодом `1`.

Цикл при определении порядка загрузки не завершает приложение с ошибкой.
Программа выводит список неупорядоченных пакетов и продолжает визуализацию.

## Тесты

Запуск:

```bash
./tests/run_tests.sh
```

Ожидаемый результат:

```text
PASS: Порядок загрузки реального npm-графа
PASS: Порядок загрузки обычного графа
PASS: Обнаружение цикла при упорядочивании
PASS: Порядок загрузки после фильтрации
PASS: Пустое имя пакета
PASS: Некорректный URL репозитория
PASS: Некорректный тестовый режим
PASS: Некорректный выходной файл
PASS: Пустая подстрока фильтрации
PASS: Пакет не найден в npm Registry
PASS: Отсутствующий конфигурационный файл

Пройдено: 11
Не пройдено: 0
```

Успешные тесты проходят через генерацию D2 и создание SVG. Если D2
завершится с ошибкой или не создаст файл, соответствующий тест завершится
неудачно.

Сетевые проверки требуют подключения к интернету.

## Основные компоненты

### `YAMLParser`

Читает и проверяет YAML-конфигурацию.

### `Configuration`

Хранит и проверяет пять пользовательских параметров.

### `NPMModels`

Описывает метаданные npm и зависимости.

### `NPMRegistryClient`

Получает метаданные напрямую из npm Registry.

### `TestRepository`

Читает и проверяет локальный JSON-репозиторий.

### `DependencyDataSource`

Переключает источник данных между npm Registry и тестовым JSON.

### `DependencyGraphBuilder`

Строит граф алгоритмом BFS без рекурсии.

### `DependencyGraph`

Хранит список смежности, версии, порядок BFS и статистику.

### `DependencyLoadOrder`

Вычисляет порядок загрузки и обнаруживает циклы.

### `D2GraphGenerator`

Преобразует граф в текст на языке D2.

### `D2Renderer`

Сохраняет временный D2, запускает D2 CLI и проверяет создание SVG.

### `main.swift`

Объединяет загрузку настроек, построение графа, анализ и визуализацию.

### `run.sh`

Собирает и запускает приложение.

### `tests/run_tests.sh`

Проверяет реальные и тестовые сценарии.

## Ограничения

Приложение:

- использует `latest` для каждого npm-пакета;
- не разрешает диапазоны версий как npm;
- не учитывает дополнительные типы зависимостей;
- выполняет HTTP-запросы последовательно;
- требует установленный D2 CLI для создания SVG.
