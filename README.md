# Dependency Visualizer

CLI-приложение на Swift для анализа и визуализации графа зависимостей
пакетов npm.

Проект выполняется по варианту 15 практической работы по дисциплине
«Конфигурационное управление».

## Текущий этап

Этап 2. Сбор данных.

На текущем этапе приложение:

- читает настройки из файла YAML;
- проверяет корректность всех параметров;
- обращается напрямую к npm Registry через HTTP;
- получает метаданные заданного пакета;
- определяет версию пакета по тегу `latest`;
- извлекает прямые зависимости выбранной версии;
- сортирует зависимости по имени;
- выводит зависимости и требования к их версиям;
- обрабатывает ошибки конфигурации, сети и npm Registry.

Для получения зависимостей не используются npm, другие менеджеры пакетов
или сторонние библиотеки.

Построение полного графа с транзитивными зависимостями будет реализовано
на этапе 3.

## Требования

Для сборки необходимы:

- macOS;
- Swift 6 или новее;
- Xcode Command Line Tools;
- подключение к интернету для работы с npm Registry.

## Параметры конфигурации

Приложение использует пять параметров:

| Параметр | Назначение |
|---|---|
| `package_name` | Имя анализируемого npm-пакета |
| `repository` | URL репозитория или путь к тестовому файлу |
| `test_mode` | Включение режима тестового репозитория |
| `output_file` | Имя создаваемого SVG-файла |
| `filter_substring` | Подстрока для исключения пакетов |

Пример `config.yaml`:

```yaml
package_name: "express"
repository: "https://registry.npmjs.org"
test_mode: false
output_file: "dependency-graph.svg"
filter_substring: "@types/"
```

Если `test_mode` имеет значение `false`, параметр `repository` должен
содержать корректный URL с протоколом `http` или `https`.

Если `test_mode` имеет значение `true`, параметр `repository` должен
содержать путь к существующему локальному файлу. Обход тестового репозитория
будет реализован на этапе 3.

Параметры `output_file` и `filter_substring` проверяются на этапе 2, но будут
использованы при построении и визуализации полного графа на следующих этапах.

## Поддерживаемый формат YAML

Для конфигурации используется простой формат:

```text
ключ: значение
```

Поддерживаются:

- строковые значения в одинарных или двойных кавычках;
- значения без кавычек;
- пустые строки;
- комментарии, начинающиеся с символа `#`.

Вложенные объекты и массивы в конфигурационном файле не используются.

## Получение данных из npm Registry

Приложение формирует запрос следующего вида:

```text
GET https://registry.npmjs.org/{package_name}
```

Для получения сокращенных метаданных используется HTTP-заголовок:

```text
Accept: application/vnd.npm.install-v1+json
```

После получения ответа приложение:

1. Проверяет код HTTP-ответа.
2. Декодирует JSON стандартным `JSONDecoder`.
3. Получает номер версии из поля `dist-tags.latest`.
4. Находит выбранную версию в объекте `versions`.
5. Извлекает объект `dependencies`.
6. Преобразует зависимости в список.
7. Сортирует список по имени пакета.

На этапе 2 учитываются только прямые зависимости из поля `dependencies`.

Не учитываются:

- `devDependencies`;
- `peerDependencies`;
- `optionalDependencies`;
- транзитивные зависимости.

## Сборка и запуск

Разрешить выполнение основного скрипта:

```bash
chmod +x run.sh
```

Запустить приложение с основным файлом конфигурации:

```bash
./run.sh
```

Запустить приложение с другим файлом конфигурации:

```bash
./run.sh tests/configs/valid.yaml
```

Скрипт собирает программу системным компилятором Swift:

```bash
xcrun --sdk macosx swiftc
```

Исполняемый файл сохраняется в папке `.build`.

## Пример результата

Для пакета `express` приложение выводит его актуальную версию, прямые
зависимости и требования к их версиям:

```text
Прямые зависимости пакета express@5.3.0:
- accepts: ^2.0.0
- body-parser: ^2.3.0
- content-disposition: ^2.0.1
...
Всего зависимостей: 28
```

Версия пакета и список зависимостей могут измениться после публикации
новой версии в npm Registry.

Если пакет не имеет прямых зависимостей, приложение выводит:

```text
Прямые зависимости пакета package-name@1.0.0:
Прямые зависимости отсутствуют.
Всего зависимостей: 0
```

## Обработка ошибок конфигурации

Приложение обрабатывает следующие ошибки:

- конфигурационный файл не найден;
- конфигурационный файл невозможно прочитать;
- строка YAML имеет неправильный формат;
- ключ или значение отсутствует;
- параметр указан несколько раз;
- обнаружен неизвестный параметр;
- строка содержит незакрытые кавычки;
- имя пакета пустое;
- URL репозитория некорректен;
- файл тестового репозитория не существует;
- `test_mode` содержит значение, отличное от `true` или `false`;
- имя выходного файла не оканчивается на `.svg`;
- подстрока фильтрации пустая;
- при запуске передано слишком много аргументов.

## Обработка ошибок npm Registry

Также обрабатываются:

- сетевая ошибка при выполнении запроса;
- некорректный HTTP-ответ;
- пакет не найден;
- HTTP-ошибка репозитория;
- поврежденные или неподдерживаемые метаданные;
- отсутствие тега `latest`;
- отсутствие версии, указанной в теге `latest`.

При любой ошибке программа выводит ее причину и завершается с кодом `1`.

## Основные компоненты

### `YAMLParser`

Читает конфигурационный файл, разбирает пары `ключ: значение` и проверяет
структуру YAML.

### `Configuration`

Хранит настройки приложения и проверяет корректность каждого параметра.

### `NPMModels`

Содержит структуры для декодирования метаданных npm и представления прямых
зависимостей.

### `NPMRegistryClient`

Формирует URL пакета, отправляет HTTP-запрос через `URLSession`, проверяет
ответ Registry, определяет версию `latest` и возвращает прямые зависимости.

### `main.swift`

Загружает конфигурацию, запускает клиент npm Registry и выводит прямые
зависимости или понятное сообщение об ошибке.

### `run.sh`

Собирает исходный код системным компилятором Swift и запускает полученную
программу.

### `tests/run_tests.sh`

Автоматически проверяет получение прямых зависимостей, обработку ошибок
всех параметров и ответ Registry для несуществующего пакета.

## Ограничения текущего этапа

На этапе 2 приложение:

- получает только прямые зависимости;
- использует версию с тегом `latest`;
- не выполняет рекурсивный обход зависимостей;
- не применяет фильтрацию пакетов;
- не поддерживает обход тестового репозитория;
- не строит граф;
- не создает SVG-файл.

Эти функции будут добавлены на следующих этапах.
